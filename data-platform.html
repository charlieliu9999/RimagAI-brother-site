院内数据查询
智能体平台

不是开放式聊天机器人，而是受控语义查询与数据治理平台。通过统一语义层、规则引擎、权限体系和审计机制，将复杂数据库查询能力封装为临床、管理和质控部门可直接使用的智能服务。

设计原则：受控查询，而非开放 NL2SQL

医院场景不适合直接做全开放 NL2SQL。数据安全要求高、底层库表结构复杂且跨系统、医疗术语存在大量别名和上下文歧义、同一问题可能存在多种统计口径、越权查看患者数据风险高。因此采用"意图识别 + 模板选择 + 参数填充"模式，所有查询走白名单模板，AI 只负责理解意图和解释结果。

与 MCOS 架构的关系

数据查询智能体是 MCOS 在数据治理域的具体实例化

L1
感知层 → 对接 HIS / EMR / LIS / RIS / PACS 数据源，只读连接或视图接入
L2
上下文层 → 统一语义模型 + 字段映射 + 同义词词典 + 查询模板，把复杂表结构封装为业务对象
L3
认知层 → 查询意图识别 + 角色权限识别 + 受控 SQL 生成 + 规则执行引擎 + 结果解释器
L4
执行层 → 汇总统计 / 明细记录 / 可视化图表 / 导出文件 / 规则解释与 SQL 说明
L5
治理层 → 多维权限控制（角色 × 组织 × 数据域 × 粒度）+ 脱敏 + 审计留痕 + 高风险导出审批

Brother 桌面端的 SQL Tool 是数据查询能力的桌面入口，数据智能体平台是院级 Web 入口。两者共享语义层和规则引擎。

自然语言提问，系统自动解析意图并生成受控查询

统计门诊检验报告正常参考值完整率
导出上个月影像检查报告与患者标识无法对应的记录
查看病房护理级别不完整的病区分布
查询医嘱执行记录中开始时间缺失的明细

服务对象

覆盖临床、管理、质控、信息等多角色需求

🏥 临床科室

科主任、医生、护士长。查询科室业务数据、医嘱执行缺失、患者全程记录、手术与麻醉匹配。

📋 医务处 / 质控办

质控专员、评审专班。查询完整性/一致性/整合性得分，导出问题明细，生成评审统计表。

📁 病案室

病案编码员、质控员。查询首页字段完整率、诊断编码缺失、首页与临床记录关联情况。

🩺 护理部

护理管理人员。查询护理级别、体征记录完整率，按病区和时间汇总异常护理记录。

💻 信息科

数据平台主管、DBA。查询指标依赖表和字段，查看规则 SQL 和执行日志，维护字段映射。

👔 院领导

院长、分管院长。查看全院数据质量总览、科室排名、趋势变化、整改闭环进展。

五层系统架构

从数据源到应用展示的完整链路

① 数据源层

对接 HIS / EMR / LIS / RIS / PACS / 护理 / 手术麻醉 / 输血 / 药房 / 主数据字典。只读连接、视图或数据集市。

② 数据治理层

统一数据目录、字段映射、主数据关系、统一编码和字典映射、宽表或主题数据集、口径版本管理。

③ 语义与规则层

语义模型管理、同义词词典、查询模板、规则库（完整性/一致性/整合性/合法性/时效性）、SQL 模板参数化执行。

④ 智能体服务层

查询意图识别、角色权限识别、NL2Intent 解析、受控 SQL 生成器、规则执行引擎、结果解释器、报表生成器。

⑤ 应用展示层

Web 门户、科室数据看板、智能问答界面、移动端轻应用、管理后台。

实施路线

分三阶段，从规则固化到全院扩展

第一阶段

规则固化与基础查询

从文档提炼规则库，建立语义模型和字段映射。首批覆盖医嘱、检验、检查三大高频域。服务信息科、质控办、病案室。MVP 8-12 周。

第二阶段

质量治理与整改闭环

增加问题分派、整改、追踪能力。趋势分析和科室排名。告警推送。整改工单与对比分析。

第三阶段

全院扩展与多角色智能体

扩展至病历、护理、药品、手术、输血等域。更强的多轮问答和口径解释。多角色门户。评审材料自动化生成。

预期价值

同时承担数据查询入口、质量治理平台和评审支撑工具三种角色

管理价值

提高全院数据查询效率，降低信息科手工取数压力，支撑等级评审和日常质控，建立统一数据口径。

业务价值

临床科室快速获取业务数据，质控部门快速定位问题记录，病案和护理部门开展持续整改。

技术价值

沉淀院内统一语义层，沉淀规则资产与数据治理资产，为后续 BI、运营分析、临床决策支持提供基础。
